# dsh-cognitive-dashboard

DSH Web GUI に追加される、読み取り専用の**「認知」タブ**。目的、現在のタスク、他に残っていること、findings、そしてセッションが始まるときの想起ブロックを1画面にまとめ、続けるか・変えるか・止めるかを判断できるようにする。

> English: [README.md](README.md)

## なぜ必要か

長い仕事は1つのセッションを越えて続く——何十回ものセッションにまたがることもある。戻ってきたとき、会話はターンの壁になっている。目的は上のほうに、現在のタスクは一番下に、後回しにした作業はどこにもない。新しいセッションは、そのどれも知らないまま始まる。

このタブは `dsh-cognitive-*` の人間側の半分です。エージェント側の半分は想起ブロックと findings 台帳です。認知レイヤーは、その材料を会話の外に置きます。エージェントはセッションの開始時に**想起ブロック**として読み、あなたは同じ3つ——目的・現在地・残り——を**「認知」タブ**で読みます。どちらの読者も、同じ判断のために同じ材料を受け取ります。狙いは記憶を大きくすることではなく、次に決めることが目的を指したままであることです。

## 何が得られるか

- タブを開けば、目的・現在のタスク・他に残っていることが見える。
- 目的ツリーは、仕事がどう分解されているか、現在のパスがどこを通っているか、どれだけ投資したか、どれだけ受入れたかを示す。
- 未対応 findings が同じ画面に、優先度順で並ぶ。
- 想起ブロックは、モデルが受け取った原文をそのまま見せる。エージェントの記憶はブラックボックスではない。
- 採点はしない。スコアも、しきい値も、ページ全体の判定もない。

効くのは、仕事がセッションをまたぎ、あなたかエージェントのどちらかが目的を再構成しなければならないときです。単発の短いタスクでは、グラフはオーバーヘッドです。次のセッションがゼロから始まってしまうほど長い仕事のときに導入してください。

## そうではないもの

- **ゲートではない。** 作業を止めず、承認も求めない。
- **ドリフト検出器ではない。** 仕事が目的からずれたかどうかを判定しない。
- **スコアではない。** 大きさと輪は投資と受入を表し、品質を表さない。
- **第二の履歴ではない。** 会話ではなく、エージェントが記録した構造を示す。

ドリフトへの効果は測っていません。確認しているのは機構です。記録がセッションを越えて残り、プロンプトに届き、ここに見える、というところまでです。

## インストールすると何が起きるか

- Chat と Trajectory の隣に**「認知」タブ**（中国語では「认知」）が付く。
- 上から4つの節: 目的ツリー、現在のタスクと他に残っていること、未対応 findings、想起ブロック。
- 読み取り専用。会話にコマンド行を追加せず、台帳にも書かない。
- ツリーと想起ブロックは `@kioju/dsh-cognitive-model` から来る。findings は findings 台帳から来るので、model がなくても表示される。
- インストール後・更新後はページを再読み込みする。ブラウザ側の部分はパッケージに同梱されている。

## インストール

DSH で **Plugins** を開き、**Add plugin** を選び、`@kioju/dsh-cognitive-dashboard` を入力します。シェルからなら同じことを次で行えます:

```
dsh plugin add @kioju/dsh-cognitive-dashboard
```

追加した時点で有効になります。**Plugins** でオフになっている場合はオンにしてください。

このタブはツリーと想起ブロックを model プラグインから描きます。model も入れてください。入っていないと、タブは「model プラグインがこのプロファイルに無い」と表示し、ツリーを描きません:

```
dsh plugin add @kioju/dsh-cognitive-model
```

`@kioju/dsh-cognitive-findings` は任意です。このタブが一覧に出す未対応 findings の、後回しキューを追加します。`@kioju/dsh-cognitive-core` は通常の依存として入ります。チェックアウトもビルドも、パッケージの隣に何かを置く必要もありません。

## 最初の5分: 「目的がまだ記録されていません」

新しいワークスペースでは **No objective is recorded yet**（日本語: 目的がまだ記録されていません）と表示されます。これは設計された空状態で、失敗ではありません。ダッシュボードは会話から目的を推測しません。エージェントがグラフに記録したことを表示するだけです。最初の `graph_write` まで、描くものはありません。

目的は一度だけ、普通のセッションで記録します。目的はあなたの意図なので、あなた自身が述べてください:

> この仕事の目的は「<1文>」です。認知グラフに `objective` として記録し、今の作業を `task/current`、他の残っている作業を `task/<key>` として記録してください。目的の根拠はこのメッセージで構いません。リポジトリは component と task を埋めるためだけに読んでください。何を書いたか1行で教えてください。

認知レイヤーは `package.json` を作成も変更もしません。model はグラフを `.dsh/cognitive-model/graph.json` に保存し、このタブはそれを読むだけです。エージェントは構造を埋めるためにファイルを読めますが、目的はあなたから来ます。

エージェントには `graph_write` ツールと、そのための常時指示があります。書き込みのあと、タブは埋まります。投影はツール結果・ターン終了・ユーザーメッセージ・コマンド完了で更新され、更新ボタンはありません。

空のままなら:

1. **Plugins** でプラグインが有効か。ページ再読み込み後にタブがあるか。
2. セッションのワークスペースは、意図したリポジトリか。グラフはプロジェクトルート単位——`.git` を持つ最も近い祖先——です。
3. エージェントは実際に書いたか。`graph_query` の結果を見せてもらうか、読んだファイルを証拠にもう一度書いてもらってください。
4. `@kioju/dsh-cognitive-model` は入っているか。入っていないと、タブは「model プラグインがこのプロファイルに無い」と表示します。

最初の目的だけが手動のブートストラップです。その後は想起ブロックが目的を各セッションに運び、エージェントが仕事の移動に合わせて `task/current` を更新します。

## 画面の見方

### 並び

1. **目的** — ルート目的の文、タスクと findings の件数、受入、ツリー。
2. **現在のタスク** — グラフが現在としているタスク、それが仕えるノード、更新時刻。その下に**他に残っていること**。
3. **未対応 findings** — 優先度順、種別、経過、状態、滞留。
4. **想起ブロック** — モデルが受け取った原文。

### 目的ツリー

中心が目的です。手段（component）は深さに応じた輪に並び、実線が `serves`、破線が `requires` です。ラベルはノードのキー（`objective`、`search` など）を切って表示します。ノードを選ぶと、完全な名前と説明が見られます。

- **大きさは投資で、重要度ではない。** そのノードと子孫に紐づくタスクと findings、実装パスに触れたコミットを数え、最大の枝を基準にした相対値で描きます。終わった枝も、投じた大きさを保ちます。
- **輪は受入。** 記録されたマイルストーンのうち、完了した割合を枝全体で合計したものです。マイルストーンがなければ輪は出ません。どちらもスコアではありません。
- **現在のパス** — 目的から現在のタスクまでの連なり — が強調され、パンくずとして繰り返されます。
- **ノードを選ぶ**と、タスク、未対応 findings、実装パス、docs、投資の内訳、マイルストーン、最終活動が見られます。検索、ズーム、パン、折りたたみが使えます。矢印キーで移動、Enter か Space で開き、Escape で閉じます。

タスクはツリーのノードとしては描かれません。大きさに数えられ、現在のタスクと他に残っていることの下に並び、選択したノードのパネルに出ます。

### 現在のタスクと他に残っていること

現在のタスクは `task/current` です。マークがなければ、最も新しいタスクが表示されます。その下の行は、どのノードに仕えるか、または `unlinked` を示します。**「未記録」は「残りがない」という意味ではありません**。何も記録されていない、という意味です。他に残っていることについても同じで、一覧は書かれたタスクを示すのであって、存在するすべてのタスクを示すのではありません。

### 未対応 findings

この節は findings 台帳を直接読みます。未対応件数と、優先度順の findings を、種別・経過・状態・滞留マーカーとともに表示します。台帳がない、台帳が読めない、台帳は読めるが未対応がない、は3つの別の状態で、節はどれなのかを表示します。

### 想起ブロック

これはモデルがターンの開始時に受け取る原文で、改行とインデントを保ちます。ツリーが描くのと同じ投影を圧縮したもので、目的、パス、現在、残り、マップ、制約、決定、リンクされた事実、経験則、そして記録された誤差が求めたときの1回だけの拘束力のない全体確認が含まれます。確認自体（`BIRDSEYE`）は含まれず、ブロックを見ても既読にはなりません。

エージェントが何を告げられたかを確かめるために読み、採点のために読まないでください。

### ラベル

**reported**（申告）、**observed**（観測）、**verified**（検証済み）は、その項目が*どのように*記録されたかを示します。人間の言葉、読んだファイルか url、実行したコマンド、のいずれかです。内容が再確認されたという主張ではありません。大事な細部は再確認してください。

### 3つの空状態

| 見えるもの | 意味 |
|---|---|
| `not recorded` / 未記録 | 何も書かれていない。新しいワークスペースでは正常。 |
| `could not read` / 読み取れません | 台帳はあるが解析できなかった。画面の他の部分は動く。 |
| `The model plugin is not in this profile` | `@kioju/dsh-cognitive-model` なしでダッシュボードだけが入っている。findings は表示される。 |

## 設計上の立場

レイアウトはデジタル庁のダッシュボードデザインの実践ガイドブックに従っています。目的ツリーが全体像として最初に来て、現在のタスクと他に残っていることが文脈として続き、未対応 findings、最後に想起ブロックがその材料として来ます。ページ全体の判定も、スコアも、しきい値もありません。不在は `not recorded` か `could not read` として示され、成功としては示されません。状態は色だけでなく、記号と語でも伝えます。

レイアウトとアクセシビリティの選択は [docs/DESIGN.md](docs/DESIGN.md)（英語）、振る舞いと制限は [docs/DETAIL.md](docs/DETAIL.md)（英語）にあります。

## 家族（dsh-cognitive-*）

`dsh-cognitive-*` は、次の判断のための材料を会話の外に保ちます。目的と仕事の分解、決めたことと制約、まだ開いていること、気づいたが後回しにしたことです。

| パッケージ | 役割 | 欠けたとき |
|---|---|---|
| `@kioju/dsh-cognitive-model` | グラフと想起ブロック | ツリーも想起ブロックも出ない。findings は表示される |
| `@kioju/dsh-cognitive-dashboard` | このタブ | エージェントは記録を続けるが、あなたに見える画面がない |
| `@kioju/dsh-cognitive-findings` | 後回しキュー | 範囲外の発見の行き先がなくなる |
| `@kioju/dsh-cognitive-core` | 共有ライブラリ | 自動で入る |

各プラグインは独立しています。全体像には model + dashboard、後回しのループには findings を追加してください。

## 開発

`npm install` はテスト依存（react、react-dom、jsdom）も入れます。`npm test` はホストの投影をグラフのスナップショットに対して動かし、クライアントを jsdom で描画します。放射状ツリー、ノードパネル、キーボード操作、検索・ズーム・折りたたみ、空状態、想起ブロック、model 不在の状態を確認します。
